# OpenAPI and Swagger

Read before writing route KDoc beyond the basics in `AGENTS.md`, or changing Ktor or Kotlin versions. Moved out of `AGENTS.md`; every rule here is as binding as one there.

**Ktor 3.6.1's OpenAPI compiler plugin requires Kotlin 2.4.0 or newer.** With an older Kotlin version, Gradle warns `OpenAPI inference will be skipped` but the build still succeeds, and Swagger loses KDoc request bodies and responses; only explicit `.describe { }` metadata survives. Keep the Kotlin version compatible when updating Ktor. **Its summary comes from the plain-text preamble before the first KDoc field, not `Summary:`**, which it ignores. Start new route KDocs with that preamble; existing `Summary:` lines are preserved alongside it. **Nested classes in bracketed KDoc type references also fail silently** (`ClassId.topLevel` could not resolve the former `NotificationSettings.Update`). Prefer a top-level request DTO that KDoc can resolve; `NotificationSettingsUpdate` now follows that pattern. Only use the runtime DSL when the type cannot be expressed through the comment syntax. `SwaggerTest` in the root project requests the actual `documentation.yaml` endpoint through the shared `installSwagger` configuration for each service and the monolith's production `monolithRoute`, without databases or external services. Run it with `./gradlew :test --tests com.bookk.server.SwaggerTest`; keep its request-operation contracts current when routes gain, lose or move request bodies.

**Describe simple lists in KDoc using `[fully.qualified.Element]+`.** For example, `Response: 200 application/x-protobuf [com.bookk.business.domain.api.employee.entity.Employee]+ Employees` generates an array schema whose `items` references the complete `Employee` schema (verified against Ktor 3.6.1 through the served Swagger document). The literal `[kotlin.collections.List<...>]` syntax still silently omits its schema. The `.describe { }` recipe in `AGENTS.md` (route recipe, step 3) is an alternative for lists and remains necessary for complex generics and nested-class references; it is not required for every simple list.

The 14 list-response `.describe { }` blocks were replaced with KDoc on Ktor 3.6.1. The complete generated monolith Swagger document was compared before and after and is identical, including all 20 response definitions, the two UUID lists, errors, descriptions and `application/protobuf` media type. `SwaggerTest` permanently checks all 14 list routes and their item schemas, including UUID formats. The final runtime block was removed after moving `NotificationSettings.Update` to the top-level `NotificationSettingsUpdate` request DTO, preserving its fields and `@ProtoNumber`s. There are no `.describe { }` blocks left in the routes. `NotificationSettingsUpdateSerializationTest` pins the legacy ProtoBuf bytes, and `SwaggerTest` checks the new component name and request fields. Swagger tests must install production's `installNegotiation()` too: runtime DSL schemas assigned outside a media-type block use the negotiated default type, which is otherwise `application/json` in a bare test application. Temporary compiler probes must have every referenced DTO on their own compile classpath, or comment type references silently fail even though the production route's module can resolve them.
